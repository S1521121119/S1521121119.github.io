身為一個部落客，我們最享受的應該是專注於寫作本身。但每次寫完一篇文章後，總有那麼一些瑣碎的步驟：手動修改檔案的 Front-matter 來加上 title 和 date，然後打開終端機，依序輸入 hexo clean、hexo generate、hexo deploy… 這一套流程走下來，寫作的流暢感也差不多被打斷了。

有沒有更懶人、更自動化的方法呢？

好吧，我必須承認，我對這個重複的流程感到有點厭倦了。如果能有一個神奇的資料夾，我只要把寫好的 .md 檔案丟進去，它就自動幫我處理好所有後續的事情，那該有多好？

這個想法催生出了一個「暫存區 (staging)」工作流的念頭。

需求說明

這個自動化流程的目標很明確：

  1. 在專案中建立一個 staging 資料夾，專門用來存放剛寫好、還未發布的 .md 文章。
  2. 執行一個腳本，它會自動遍歷 staging 裡的所有文章。
  3. 腳本要足夠聰明，能讀取每個檔案的「最後修改時間」，並將其作為文章的發布日期（date）。
  4. 同時，腳本也應該直接使用檔案的名稱作為文章的標題（title）。
  5. 在處理完所有檔案後，自動執行標準的 Hexo 部署指令。
  6. 如果部署成功，就自動刪除 staging 裡面的原始檔案，完成清理。

解決方案：萬能的批次腳本

要在 Windows 環境下實現這個目標，最直接的工具就是我們熟悉的批次腳本（Batch Script, .bat）。它雖然古老，但用來處理這類檔案操作與指令執行的串接任務，依然是綽綽有餘。

腳本登場

這就是我們最終的解決方案，一個名為 stage_and_deploy.bat 的腳本。

使用方法

現在，整個寫作到發布的流程變得極其簡單：

  1. 將上面這段程式碼儲存成 stage_and_deploy.bat 檔案，並放在您的 Hexo 部落格根目錄。
  2. 當你寫完一篇文章，例如 my-awesome-post.md，直接把它丟到 staging 資料夾裡。
  3. 按兩下執行 stage_and_deploy.bat。

然後就沒你的事了。腳本會接管一切，喝杯咖啡回來，文章就已經發布在你的網站上了。

總結

這個小小的自動化腳本，雖然技術上不複雜，但它解決了寫作流程中的一個痛點。透過建立一個明確的「暫存區」，我們將「寫作」和「發布」這兩個行為徹底分開，讓自己可以更專注於內容創作。這或許就是身為開發者，折騰工具最終的樂趣所在吧。
